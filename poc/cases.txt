# PoC capture cases (KI 1, U98 L1.5D). Format:
# Cases marked --blank-disk were captured booting with the all-zero disk
# (tools/make_blank_chd.sh), before the real kinst.chd was available.
#   name  function  hit  [capture options...]
# A case stops at the hit-th call of the function that satisfies --when
# (a MAME debugger expression; the caller's return address identifies the
# call site). Plain hit indices are not stable across MAME runs: the game's
# disk write/verify loop does not repeat the same number of times.
# "real" cases capture a call made by the game itself during boot.
# "-interp" cases repeat a real case with MAME's MIPS3 interpreter instead
# of its DRC (two independent MAME CPU back ends).
# "syn" cases (always run with the interpreter, see tools/mame_capture.py)
# stop at a real call and overwrite inputs first; the original
# code still runs inside MAME, but the inputs are synthetic.

# FPU functions (single precision). Selections by exact input tuple come
# from `list` runs; calls late in a run may not recur in a capture run (the
# list run stops at every call, which appears to perturb the CPU/DCS
# interleaving), so late cases are selected by property instead. Captured with the real kinst.chd, during
# attract mode / gameplay. 0x8801a1e8 takes its inputs in registers, so only
# real calls (DRC) are used: MAME's interpreter truncates CVT.W.S instead of
# rounding per FCSR.RM, so it cannot serve as the oracle for that function.
# 0x880176f0 reads globals at 0x88035e30-0x88035e40; its synthetic cases
# inject memory only, which the DRC honours.
